# Запуск и контракты ML-части

Состояние на 25.10.2026. Python 3.12. Область изменений ограничена ingestion,
ML, их тестами и необходимыми точками интеграции моделей/API. Исходные материалы,
frontend, калькулятор, авторизация, экспорт, Docker и worker не изменялись.

## Установка

PowerShell, из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e './backend[dev]'
cd backend
```

Для embeddings дополнительно:

```powershell
python -m pip install -e '.[ml]'
python -c "from huggingface_hub import snapshot_download; snapshot_download('intfloat/multilingual-e5-small', revision='614241f622f53c4eeff9890bdc4f31cfecc418b3', local_dir='ml/artifacts/models/multilingual-e5-small', allow_patterns=['*.json','*.safetensors','tokenizer.*','sentencepiece.*','*.model'], ignore_patterns=['onnx/*','openvino/*'])"
```

Модель загружается один раз этой явной командой. Инференс использует только
локальные файлы, CPU, два потока, batch size 8, максимум 512 токенов. Базовый
backend не импортирует torch и не требует `[ml]`. Проверенная среда приведена в
отчёте; изолированная установка сама разрешает зависимости SciPy/NumPy.

## Пакетная обработка

Все команды ниже выполняются из `backend/` с активированным окружением.

```powershell
# Excel -> нормализация -> baseline NLP -> признаки -> scoring -> локальные JSON
python -m ingestion.cli run --excel 'C:\Users\timof\Downloads\Хакатон_2026_фактура.xlsx' --output ml/artifacts/baseline --as-of 2026-10-24

# Только нормализация Excel
python -m ingestion.cli excel --excel 'C:\Users\timof\Downloads\Хакатон_2026_фактура.xlsx' --output ml/artifacts/excel

# Локальный XML или ZIP ФНС -> потоковый JSONL (персональные записи остаются локально)
python -m ingestion.cli fns --path 'C:\data\rsmp-61.zip' --region 61 --output ml/artifacts/fns-61.jsonl

# Совместный анализ Excel и предоставленного XML/ZIP
python -m ingestion.cli run --excel 'C:\Users\timof\Downloads\Хакатон_2026_фактура.xlsx' --fns 'C:\data\rsmp-61.zip' --output ml/artifacts/combined --as-of 2026-10-24

# Гибридные рекомендации с E5
python -m ingestion.cli nlp --input ml/artifacts/baseline/normalized.json --semantic --model-path ml/artifacts/models/multilingual-e5-small --revision 614241f622f53c4eeff9890bdc4f31cfecc418b3 --threshold 0.84 --output ml/artifacts/hybrid --as-of 2026-10-24

# Пересчитать score с сохранением уже рассчитанных NLP-рекомендаций
python -m ingestion.cli score --input ml/artifacts/hybrid/normalized.json --output ml/artifacts/rescored --as-of 2026-10-24
```

`run` также принимает `--semantic`, `--model-path`, `--revision`, `--threshold`,
`--catalog`. Дата `--as-of` обязательна: время расчёта рейтинга воспроизводимо.
`normalized.json` содержит `format_version=mmd-pipeline-1`, исходные нормализованные
записи, уникальные компании, проекты, рекомендации, рейтинги, конфигурацию и отчёт.
`quality.json` содержит только агрегаты. Оригинальный Excel проверяется по SHA-256
до/после обработки и не перезаписывается.

## Данные и matching

Листы определяются по заголовкам; `МОД3_*` пропускаются до чтения содержимого.
Pandas/openpyxl читают идентификаторы строками. Цифры, уже потерянные в исходном
числовом значении, не восстанавливаются догадкой. Для фактуры все идентификаторы
были строками. ИНН проверяется обеими контрольными цифрами, ОГРН/ОГРНИП — остатком
от деления. Валидный ИНН первичен; конфликт другого валидного идентификатора требует
разбора. Сходство имени и территории даёт `requires_review`, без автоматического merge.

Муниципалитеты приводятся к общим названиям; соответствие городов районным
территориям задано в `ingestion/municipalities.json`. Для иных регионов справочник
можно расширять. Если муниципалитет неизвестен, используется явно помеченный
региональный агрегат. Координаты остаются NULL.

Самостоятельное значение `136` в адресных/контактных полях фактуры не найдено.
Поэтому оно не удаляется автоматически. Для проверенной выгрузки библиотечный
`read_excel(..., placeholder_fields=('Район', 'Город'))` разрешает очистку только
названных полей. Число 136 в численности, инвестициях и прочих показателях сохраняется.
Контактные сведения не переносятся в признаки или публичные отчёты.

FNS-адаптер следует [официальному описанию набора РМСП](https://www.nalog.gov.ru/opendata/7707329152-rsmp/)
и [XSD от 12.05.2026](https://file.nalog.ru/opendata/7707329152-rsmp/structure-12052026.xsd).
Обрабатываются `Документ`, `ОргВклМСП`, `ИПВклМСП`, `СведМН/@КодРегион`,
`СвОКВЭДОсн`, `ДатаСост`, `ДатаВклМСП`, `ССЧР`. Фильтр региона не использует
начало ИНН. ZIP читается без извлечения на диск, XML — через iterparse с освобождением
элементов, без загрузки внешних сущностей/DTD. Ошибки отдельной записи считаются,
синтаксическая ошибка останавливает только повреждённый XML-member. Это не полная
XSD-валидация. Файл всей России автоматически не скачивается.

CLI `fns` потоковый. Совместный `run` хранит отобранную региональную выборку и
признаки в памяти: её размер нужно учитывать при импорте большого региона.
Онлайн-API ФНС, обход капчи и загрузка общероссийского реестра отсутствуют.

## NLP

`ml/needs_catalog.yaml` задаёт пять прежних category IDs, регулярные выражения,
исключения, отрицательные контексты и отраслевые сценарии. Используются границы
слов и формы слов через явно заданные regex. Общие «информационный», «безопасность»,
«ср» не являются достаточными маркерами.

Explicit — точный фрагмент исходного текста с сохранением регистра; inferred —
гипотеза с `evidence=null` и объяснением. Не более трёх рекомендаций; при отсутствии
контекста — `insufficient_data`. `probability` всегда NULL. Уверенность характеризует
основание текстового вывода, а не шанс продажи.

E5 следует [карточке модели](https://huggingface.co/intfloat/multilingual-e5-small):
`query:` для проекта, `passage:` для категории, нормированные векторы и cosine
similarity. Каталог кешируется по версии модели/конфигурации/текстов. Явные правила
приоритетны; семантика ранжирует только допустимые по контексту гипотезы, подавленные
отрицанием категории исключаются. Ниже порога семантический сигнал отвергается,
отраслевой baseline сохраняется. При недоступной модели статус причины виден в JSON,
baseline продолжает работать. Порог 0.84 предварительный, без калибровки на тестовых метках.

## Scoring

`ml/scoring_config.json` хранит экспертные веса и масштабы. Рейтинг компаний:
отрасль 0.30, размер 0.20, инвестиции 0.30, время предложения 0.20.
Отраслевая релевантность задаётся справочником по ОКВЭД. Размер —
`min(log1p(employees)/log1p(250), 1)`; при неизвестной численности используется
явно названный proxy категории МСП (0.2/0.55/0.85), а не выдуманное число работников.
Инвестиции нормируются логарифмом бюджета до 10 000 млн руб.; при неизвестном бюджете
подтверждённых проектов — количеством до пяти. Если подтверждённых проектов нет,
фактор неизвестен. Временной сигнал учитывает указанные годы; стадия из них не выводится.

По доступным факторам веса перенормируются. Для числа нужны минимум два фактора
и покрытие исходных весов >=0.4; иначе score=NULL. Возвращаются значения,
доступность, исходные/эффективные веса, вклады, качество, версия, ограничения.
Уверенная связь с проектом и контекстный NLP-сигнал могут поднять отраслевой фактор
до 0.8 один раз. Cosine similarity сама по себе score не увеличивает.

Территории агрегируются как муниципалитет × отрасль. Логарифмы наблюдаемых количества
компаний, проектов и бюджета нормируются по загруженной выборке; веса 0.5/0.3/0.2.
Общий бюджет строительства не является стоимостью телеком-услуг. Истории выручки
в фактуре нет; рост не моделируется. Отсутствие компаний/проектов в загруженной
выборке описывает только эту выборку и не доказывает отсутствие бизнеса/инвестиций.

«Белые пятна» сравнивают территории внутри отрасли и уровня агрегации, минимум
четыре наблюдения и вариативность обоих показателей. Пороги P75/P25 интерполируются.
Без известности присутствия — `insufficient_presence_data`, без достаточной выборки —
`insufficient_comparison_data`. Условную клиентскую базу нельзя выдавать за реальные
контракты. Реальные данные поэтому не дали подтверждённых белых пятен.

Старый `score_potential` сохранён для совместимости как нижняя оценка по фиксированным
весам, с отдельной доступностью факторов. Pipeline использует новые объяснимые
рейтинги; heatmap предпочитает сохранённые территориальные snapshots.

## PostgreSQL и API

Используются прежние Company, CompanyMatch, CompanyMetric, SourceRecord,
InvestmentProject, ProjectNeed и ScoringSnapshot. Муниципалитеты — дочерние Region.
У происхождения есть стабильный hash без fetched_at, источник, external ID, дата выгрузки.
Детали рекомендаций хранятся в новом nullable `ProjectNeed.details_json`.
`ScoringSnapshot.score` допускает NULL для отказа от оценки. `factors_json` содержит
один объект со всеми факторами, качеством, версией и объяснением; для регионов — отрасль.
Повторный импорт идентичных данных не увеличивает число исходных записей,
компаний, матчей, проектов, потребностей и snapshots. CLI выполняет одну транзакцию;
параллельные конкурентные импорты одного источника не поддерживаются.

Сначала заполните обычные переменные окружения приложения (пример `.env.example`).
Нужны DATABASE_URL, SECRET_KEY, TOTP_ENCRYPTION_KEY. Пароли в команды документации
не вшиты. На существующей базе с таблицами каркаса:

```powershell
alembic upgrade head
python -m ingestion.cli import-db --input ml/artifacts/hybrid/normalized.json
```

В репозитории до этих изменений не было baseline-ревизии создания таблиц.
Новая миграция аддитивная и намеренно не создаёт/переписывает чужие таблицы.
Для **новой пустой выделенной БД** сначала создайте исходную metadata:

```powershell
@'
from sqlalchemy import text
from app.db.session import engine
from app.db.base import Base
import app.models
with engine.begin() as connection:
    connection.execute(text("CREATE EXTENSION IF NOT EXISTS postgis"))
    Base.metadata.create_all(connection)
'@ | python -
alembic stamp head
```

Это подготовка новой БД; на существующей применяется `upgrade head`. Downgrade
не удаляет строки и отказывается восстановить NOT NULL, если есть отказанные оценки.
На этапе 2 миграция и PostGIS проверены на отдельном переносимом PostgreSQL 17.11 /
PostGIS 3.6.2. Общая/рабочая БД не использовалась. Полные результаты — в
[ml-stage2-report.md](ml-stage2-report.md).

Для повторения создайте отдельный экземпляр с уже распакованными официальными
бинарниками PostgreSQL/PostGIS (Windows):

```powershell
python -m ingestion.test_postgres --binaries ml/artifacts/stage2/pgsql --directory ml/artifacts/my-pg-test --port 55449
$owned = Get-Content ml/artifacts/my-pg-test/test-database.json -Raw | ConvertFrom-Json
$env:DATABASE_URL=$owned.database_url
$env:MMD_TEST_DATABASE_URL=$owned.database_url
$env:MMD_TEST_DATABASE_TOKEN=$owned.token
$env:PGCONNECT_TIMEOUT='3'
```

Затем создайте metadata и примените миграцию в этой новой БД, как указано выше,
задайте MMD_EXCEL_PATH и MMD_FNS_JSONL (путь к региональному JSONL из полного аудита),
выполните `python -m pytest -m integration -q`. Тесты проверяют имя mmd_ml_test_* и
marker-комментарий, откатывают изменения даже после session.commit через savepoints.
Если marker не совпал, тесты завершаются ошибкой, а не пишут в неизвестную БД.
Реквизиты test-database.json и init-password.txt остаются локально в artifacts.

HTTP ничего не скачивает и не выполняет тяжёлый inference:

SQL-импорт обрабатывает источники, компании, provenance и company snapshots
пакетами до 1 000 записей; транзакция остаётся у вызывающего кода. Повторные
идентичные источники/оценки не создают дублей. Сходство имени не объединяет
объекты, конфликт валидных идентификаторов прерывает импорт с rollback.

| URL под `/api/v1` | Результат |
|---|---|
| `GET /investments/{id}/needs` | Сохранённые ProjectNeed, прежние поля и optional evidence_type/reason/semantic_similarity/confidence_label/data_quality |
| `GET /companies` | Прежние поля и последнее сохранённое score |
| `GET /companies/{id}/score` | Детальные факторы/покрытие/объяснение; `not_calculated`, если расчёта нет |
| `GET /radar/heatmap` | Сохранённые рейтинги; неизвестные выручка/рост/присутствие — NULL |
| `GET /radar/white-spaces` | Прежний список, пустой при неподтверждённом присутствии |

Для старых ProjectNeed новая metadata остаётся NULL до пакетного пересчёта. Стадия
инвестпроектов из Excel — `unknown`; годовая точность хранится в source payload.
Точная planned_start/planned_end и timeline-события не выдумываются.

## Контракт для команды

- Владелец `frontend/src/types/api.ts`, `frontend/src/pages/RadarPage.tsx` и
  `frontend/src/features/radar/MapView.tsx`: предусмотреть NULL для отсутствующих
  revenue_sum/growth_share/presence_score, показать `presence_status`, optional
  `model_version`/`aggregation_level`. Объекты без координат показывать списком.
- В интерфейсе потребностей использовать evidence_type, различать цитату и гипотезу,
  probability=NULL не превращать в 0%. Все старые URL/фильтры сохранены.
- Владелец БД: применить аддитивную миграцию и проверить цепочку Alembic на своей
  базе. Владелец worker может вызывать `ingestion.pipeline.run_pipeline` и
  `ingestion.persistence.import_result` в фоновой задаче; worker не менялся.
- Полная официальная региональная выборка ФНС уже проверена на этапе 2.
  Для расширения возможностей нужны проверенные связи инициаторов с ИНН, присутствие клиентов,
  финансовый временной ряд и исходы реальных продаж. Эти данные не синтезируются.
