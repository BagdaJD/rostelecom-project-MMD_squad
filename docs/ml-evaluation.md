## Что реализовано и исправлено

Добавлены Excel/FNS-адаптеры, справочник муниципалитетов, matching, признаки,
пакетный pipeline/CLI, каталог NLP, E5, гибрид, оценка по ручной разметке, рейтинги
компаний/территорий, безопасный поиск белых пятен, хранение и чтение результатов API.
Исправлены контрольные цифры 12-значного ИНН, ложное объединение по имени,
нестабильный source hash, повторное создание CompanyMatch, JSON-сериализация дат,
псевдовероятности NLP, ложные подстрочные маркеры, повторный подсчёт компаний/выручки,
сравнение одинаковых или несоседних годов и выдуманное нулевое присутствие.

Исходный тест, требовавший probability 0.6 от правила, обновлён: теперь проверяет
NULL, evidence_type=explicit и точную исходную цитату. Это намеренное изменение
устаревшего ожидания, согласованное с заданием пользователя.

Окончательный прогон: **83 passed, 5 skipped, 0 failed**, 40.89 с; два предупреждения
сторонних библиотек. Реальные Excel и E5 были включены указанными переменными.
JUnit: `backend/ml/artifacts/pytest-final.xml`. Полный Ruff: **30 замечаний**, ни одно
не относится к изменённым файлам. Проверка Ruff всех изменённых/new Python-файлов
и `git diff --check` прошли.

Unit-тесты покрывают ИНН/ОГРН, ведущие нули, пропуски/заглушки, даты/числа,
отрицательные контексты/общие слова, точность цитат, отсутствие фиктивной evidence,
multi-label/top-3, E5 prefix/батчи/кеш/нормы, fallback, ручные метрики, вклады/веса,
монотонность/повторяемость/пропуски, исключение неподтверждённых связей, квантили и
предохранители поиска белых пятен. Реальная E5 запускалась, а не заменялась test double.

SQLite проверяет ORM persistence/API с NULL geometry. Это отдельная проверка,
которая не заменяет PostgreSQL/PostGIS: типы Geometry при создании тестовой схемы
заменены Text, функции геометрии служат только для NULL. Реальные записи Excel
дважды прошли SQL-импорт; числа Company/CompanyMatch/SourceRecord/InvestmentProject/
ProjectNeed/ScoringSnapshot не увеличились. Проверены единицы измерения бюджета:
136 млн руб. сохраняется как 136 000 000 руб., это общий бюджет строительства.

PostgreSQL недоступна на localhost:5432. Четыре существующих DB-теста и один новый
пропущены; миграция на настоящем сервере не проверена. Для проверки после запуска

## Ручная разметка и оценка

```powershell
python -m ingestion.cli annotation-template --input ml/artifacts/baseline/normalized.json --output ml/artifacts/annotations.json
python -m ml.evaluation --gold ml/artifacts/annotations.json --predictions ml/artifacts/baseline/normalized.json ml/artifacts/hybrid/normalized.json --output ml/artifacts/evaluation.json
```

Шаблон содержит текст и внешний project_id, без автоматически проставленных меток
или рекомендаций. Для каждого проекта эксперт заполняет:

1. `split`: dev для разработки правил/порога, test для итоговой проверки.
2. `explicit_categories`: список только прямо упомянутых категорий; [] означает
   проверенное отсутствие; null означает, что проект ещё не размечен.
3. `explicit_evidence`: точные цитаты для каждой explicit-категории.
4. `inferred_relevant`: словарь category -> true/false с экспертной оценкой каждой
   inferred-рекомендации top 3 обоих сравниваемых методов; null = не оценено.
5. `annotator`: идентификатор эксперта. Спорные случаи согласовать независимо.

Метрики: precision/recall/F1 по категориям и macro, число false-positive explicit,
inferred Precision@3 с фиксированным знаменателем 3, число воздержаний. Категории
без поддержки имеют F1=0 и входят в macro по фиксированным пяти категориям.
Неразмеченные поля не интерпретируются как отрицательные метки. Пропущенные
предсказания для размеченного проекта и неверные цитаты приводят к ошибке оценки.
Программа не подбирает порог; делайте это только на dev, test оставьте нетронутым.

На созданном пустом шаблоне evaluator запущен для baseline и hybrid, оба вернули
`not_evaluated`. Precision, Recall и F1 не заявлены. Для проверки точности нужна
независимая ручная разметка; для оценки приоритизации лидов — реальные исходы продаж.
