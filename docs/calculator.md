# Калькулятор сделок (модуль 3)

Считает проект диспетчеризации инженерных систем здания по справочникам кейса и выдаёт
вилку «минимум / оптимум / максимум» с маржой, график маржинальности, сравнение с
аналогами, шанс выиграть, схемы оплаты, КП в Word и выгрузки CSV/CRM.

## Как встроен в проект

Калькулятор — отдельный пакет со своими таблицами и своим адресом API. Общий код не меняется:

| Что | Где |
|---|---|
| Расчёт себестоимости | `backend/ml/deal_cost.py` |
| Вилка и оптимум | `backend/ml/deal_pricing.py` |
| Шанс выиграть (scikit-learn) | `backend/ml/win_model.py` |
| Сервис, таблицы `calc_*`, КП, CSV, загрузка данных | `backend/modules/deal_calculator/` |
| API `/api/v1/calculator/*` | `backend/app/api/v1/endpoints/calculator.py` |
| Данные кейса | `data/case/case_data_2026.xlsx` → `backend/modules/deal_calculator/data/case_bundle.json` |

Здесь только бэкенд. Страницу калькулятора (`frontend/src/pages/CalculatorPage.tsx`) делает
фронтенд поверх API, описанного ниже. Прежний `POST /deals/estimate` и `ml/deal_estimator.py`
продолжают работать как раньше.

## Запуск

Из папки `backend` (в Docker — `docker compose … exec backend …`):

```bash
alembic upgrade head                     # схема, включая calc_*
python -m modules.deal_calculator.seed    # данные кейса
```

Повторный запуск безопасен: справочники обновляются, сделки не дублируются.
В Compose миграции и оба seed выполняет сервис `init`. Флаг `--create-all` оставлен
для совместимости со старым демо; обычный запуск его не использует.
Шанс выиграть считает scikit-learn (`pip install -e ".[ml]"`). Без него калькулятор работает
на упрощённой модели (однофакторная логистика по ближайшим сделкам) и сообщает об этом в
ответе (`win_model.type = single_factor`).

Пересобрать бандл из xlsx кейса (нужен openpyxl): `python3 infra/scripts/import_case_xlsx.py`.

## Что нужно фронтенду

Сценарий страницы `/calculator`:

1. `GET /calculator/catalog` — всё для формы: позиции по системам (`systems`), типы объектов,
   уровни, регионы с коэффициентами (`id` региона передаётся в расчёт), схемы оплаты и
   параметры для пересчёта на клиенте (`settings`: ставка рассрочки, срок сервиса и т. п.).
2. `POST /calculator/estimate` — расчёт. Минимум: `object_type` и `area_m2` (состав подберётся по
   площади) или `items` (коды позиций и количества). В ответе: `estimate` (min / optimum / max),
   `cost` (себестоимость, статьи, строки состава, факторы), `margin`, `win_probability`,
   `curve` — точки «цена → маржа, шанс, ожидаемая прибыль» для графика и ползунка,
   `comparables` — аналоги с наценкой и исходом, `payment_options`, `win_model` — модель и вклад
   факторов в п.п., `warnings`.
3. `POST /calculator/estimates/{id}/approve` с `{"price": …}` — утвердить цену (роль менеджер
   или администратор); ниже себестоимости — 422 с текстом ошибки.
4. Файлы: `GET …/proposal?variant=client|internal` (Word; `internal` — только аналитик или
   администратор, иначе 403) и `GET …/csv?kind=deals|comparables|crm`.

`/calculator?project=ID` — черновик из инвестпроекта навигатора:
`GET /calculator/draft/{project_id}` возвращает готовый `request` для шага 2 и пояснения
(`explain`), откуда взяты тип объекта, площадь и срок. Кнопка на карточке проекта:

```tsx
<Link to={`/calculator?project=${project.id}`}>Оценить сделку</Link>
```

## API

| Метод | Назначение |
|---|---|
| `GET /calculator/catalog` | каталог по системам, уровни, регионы с коэффициентами, параметры |
| `POST /calculator/estimate` | расчёт: себестоимость, вилка, маржа, аналоги, кривая, оплата, шанс |
| `POST /calculator/estimates/{id}/approve` | утвердить цену (не ниже себестоимости) — она идёт в КП |
| `GET /calculator/estimates/{id}/proposal?variant=client\|internal` | КП в Word: для заказчика / с обоснованием цены |
| `GET /calculator/estimates/{id}/csv?kind=deals\|comparables\|crm` | CSV для Excel или для импорта в CRM |
| `GET /calculator/draft/{project_id}` | черновик параметров из инвестпроекта |

CSV `deals` и `comparables` — для Excel: UTF-8 с BOM, разделитель «;», десятичная запятая.
CSV `crm` — для импорта: RFC 4180 (разделитель «,», десятичная точка), поля
`externalId, title, amount, currency, stage, companyName, inn, source, comment`; `amount` —
утверждённая цена или оптимум.

## Как считается

1. **Себестоимость** «снизу вверх»: оборудование по каталогу МОД3_Таб4, работы — доли
   МОД3_Таб3 (ПИР 10 %, ПНР 15 %, шеф-монтаж 5 %) с коэффициентом сложности группы, уровень
   проекта МОД3_Таб2, региональный коэффициент МОД3_Таб1, срочность, уникальность, резерв на
   нестандарт. Контрольный пример (ТЦ в Ростове, 55 приборов, «продвинутый») =
   **668 528,74 ₽**, закреплён тестом.
2. **Вилка** = себестоимость × наценка похожих сделок (цена ÷ себестоимость): минимум —
   max(себестоимость / (1 − 15 %), Q25), максимум — Q75 (квантили взвешены сходством),
   оптимум — максимум «(цена − себестоимость) × шанс выиграть» внутри вилки. Регион учтён в
   себестоимости и у нас, и у аналога, поэтому от аналогов переносится только наценка.
3. **Шанс выиграть** — логистическая регрессия на 7 признаках: наценка, тип объекта, площадь,
   уровень, регион, схема оплаты, госзаказчик. Проверка по времени (обучение на ранних 75 %,
   проверка на последних 25 %), рядом — базовая модель «только наценка». В ответе — вклад
   каждого фактора в п.п. относительно типичного проекта. Почему не CatBoost —
   [`calculator-win-model.md`](calculator-win-model.md).
4. Если похожих сделок меньше трёх — вилка от целевых маржей 15 / 25 / 35 %.

**Сходство аналогов:** тип проекта 0,30 + тип объекта 0,15, площадь 0,15 (одинаковая → 0,15,
отличие в 3 раза → 0), регион 0,10, набор систем 0,30.

## Что из кейса, а что допущение

| Параметр | Значение | Источник |
|---|---|---|
| Цены и коэффициенты сложности 20 позиций | МОД3_Таб4 | кейс |
| Доли ПИР / ПНР / шеф-монтажа | 10 / 15 / 5 % | кейс |
| Уровень проекта | 1,0 / 1,3 / 1,6 | кейс |
| Региональный коэффициент | 1,0…1,45 по зонам | кейс |
| К чему применять сложность | `DEAL_COMPLEXITY_MODE=works` | **допущение**, вопрос куратору |
| Срочность | 1 + 0,5·(1 − срок/норма), ≤ 1,3; норма = 1 мес + 1 мес/100 приборов | допущение |
| Уникальное решение | ×1,15 | допущение |
| Резерв на нестандарт | +20 % | допущение |
| Минимальная / целевая маржа | 15 % / 25 % | допущение |
| Рассрочка и сервис | 20 % годовых, абонентская плата 5 000 ₽/мес | допущение |
| История сделок и исходы | 400 сделок | **синтетика** (`retro_price_basis=synthetic`) |

`DEAL_COMPLEXITY_MODE` (переменная окружения): `works` — сложность умножает работы
(668 529 ₽ на контрольном примере), `installation` — (k − 1) × оборудование как статья
«монтаж» (770 964 ₽), `equipment` — умножает цену оборудования (836 455 ₽).

Истории сделок в кейсе нет, поэтому 400 сделок сгенерированы
(`infra/scripts/import_case_xlsx.py`): себестоимость — той же формулой, наценка — около ×1,36,
исход — по логистической кривой с заложенными эффектами (госзаказчик −0,05 к порогу,
экспертный уровень +0,03, сервисная оплата +0,025). Модель находит их — это проверка, что она
работает, а не знание о рынке. В ответе API (`retro_price_basis`) и в КП такие расчёты
помечены «демо».

## Честные предупреждения

- нет аналогов → вилка не выдумывается, расчёт от целевых маржей с предупреждением;
- все аналоги синтетические → плашка «Демо: аналоги синтетические», пометка в КП;
- оптимум упёрся в нижнюю границу → подсказка проверить состав и уровень;
- нестандартные позиции → «цена требует подтверждения пресейлом»;
- цену ниже себестоимости утвердить нельзя (422).

## Реальные контракты

Контракты из ЕИС вносятся вручную по шаблону `data/contracts/contracts_template.csv` —
[`calculator-contracts.md`](calculator-contracts.md). Расчёт по площади рассчитан на здания;
для насосных станций и котельных стоимость определяют шкафы управления, которых нет в
каталоге кейса, — такие объекты нужно считать по составу.

## Таблицы

`calc_region`, `calc_position`, `calc_dictionary`, `calc_deal`, `calc_estimate` — без внешних
ключей на таблицы других модулей. При генерации миграций Alembic добавьте в
`alembic/env.py` строку `import modules.deal_calculator.models`, чтобы autogenerate видел эти
таблицы.
