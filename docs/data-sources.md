# Источники данных, лицензии и ограничения

Каркас намеренно не обращается к внешним источникам из HTTP-запроса: загрузка выполняется
воркером, интерфейс читает нормализованные записи из БД (ТЗ 5).

## Что подключено сейчас

| Источник | Статус | Данные |
|---|---|---|
| `demo` (`data/seed/demo_bundle.json`) | включён | синтетические, генерируются `infra/scripts/make_demo_bundle.py` |
| `fns` (ФНС, открытые данные) | заглушка | требуется проверка API и условий использования |
| `eis` (ЕИС zakupki.gov.ru) | заглушка | требуется проверка каталога, частоты запросов и лицензий |
| Реестры инвестиций, кадастр | не реализованы | см. ограничения ниже |

Список доступных источников: `ingestion.enabled_sources()`. Реальные адаптеры включаются
только при явном согласии на обработку (`consent_granted=True`) — это защита от «случайно
пошли в продакшн-источник» на демо.

## Правила, обязательные для любого адаптера

1. Проверить условия использования, наличие официального API и допустимую частоту запросов
   **до** написания кода загрузки. Обход защит, капчи и ограничений — запрещён.
2. Проверить лицензию и допустимость повторного распространения: вывод в CRM-экспорт —
   это уже распространение.
3. Для каждой загрузки создавать `source_record` с `payload_hash`, датой и `license_note`.
4. Не подменять пропуски нулями; сохранять период показателя и единицу измерения.
5. Не собирать персональные данные сотрудников и контактные лица «на всякий случай».

## Что это меняет в продукте

- **Кадастр не используется.** Стадия «стройка» определяется по реестрам и описаниям, а не по
  разрешениям на строительство; в UI это помечено как оценка по доступным данным.
- **Присутствие клиентов (`customer_presence`) синтетическое.** Без него «белое пятно»
  считается на модельном покрытии, и в объяснении это указано прямо.
- **Цены на оборудование и ПО (`position_price`) синтетические.** В карточке расчёта
  выводится предупреждение, а не «рыночная» цена.
- **Истории выигранных сделок нет.** Калькулятор работает как поиск аналогов, а не как
  валидированный прогноз: метрика MAE появится только после появления `retro_price_basis=contract`.

## Перед пилотом

- получить от заказчика легальные выгрузки или договориться о доступе к витринам;
- подтвердить правовые основания обработки и внутренние правила ИБ;
- заменить синтетические справочники на корпоративные (региональные коэффициенты, прайсы);
- пересчитать `mv_*` витрины на реальном объёме и проверить цель «до 2 секунд».
