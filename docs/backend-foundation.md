# Схема данных и запуск backend

Backend построен как модульный монолит. Общие компании, проекты и источники используются
радаром, навигатором и калькулятором. Текущая архитектура описана в
[BACKEND_ROADMAP.md](BACKEND_ROADMAP.md).

## Миграции

| Ревизия | Назначение |
|---|---|
| `20261025_0001` | Начальная схема общих и `calc_*` таблиц, PostGIS и пространственные индексы |
| `20261025_0002` | Дата создания уведомлений, включая существовавшие записи |
| `20261025_0003` | Происхождение компаний, география, синтетические данные и точность дат |
| `20261025_0004` | Состояние MFA, одноразовость кодов и серверные сессии |
| `20261025_0005` | Журнал событий, доставка, фоновые задачи, витрины и артефакт модели |

Схема содержит 43 таблицы и три materialized view. Начальная миграция зафиксирована
и не строится из изменяемых ORM-моделей. Схема создаётся через `alembic upgrade head`;
генерировать новую начальную ревизию при каждом запуске не требуется.

Миграция сессий отзывает прежние сессии: пользователям потребуется повторный вход.
Миграция фоновых задач сохраняет прежние уведомления и рыночные сигналы.
Для старой БД, созданной через `create_all`, сначала нужна сверка схемы с миграциями.

## Запуск

Состав окружения: PostgreSQL/PostGIS, Redis, API и worker. Инициализация выполняет
миграции, импорт данных кейса, загрузку калькулятора и подготовку витрин/модели.
API и worker используют одну конфигурацию и каталог экспортов.

- [Серверный запуск](server-deployment.md): Linux/Python или Docker.
- [Локальный запуск без Docker](background-and-run.md): Windows/Python.
- `infra/scripts/dev.ps1`: Compose, логи, пользователь и изолированные тесты.
- `infra/scripts/native.ps1`: проверка сервисов, инициализация, API и worker.

`/health` проверяет процесс. `/api/v1/ready` проверяет БД, ревизию схемы и Redis.
Один успешный `/health` не подтверждает готовность пользовательских операций.

## Проверка

Переносимые тесты проверяют HTTP-контракты и бизнес-правила на SQLite без пространственных
операций. PostgreSQL SQL миграций проверяется offline. Интеграционные тесты проверяют
реальные миграции, соответствие ORM, PostGIS, MV, конкурентность и RQ.

В CI и изолированном тестовом Compose задан `REQUIRE_INTEGRATION=1`: отсутствие сервисов
считается ошибкой. Полный набор запускается на отдельной тестовой БД и Redis,
а не на данных демонстрации. Текущий локальный результат — 154 успешных переносимых теста;
21 интеграционная проверка ожидает серверного окружения.
