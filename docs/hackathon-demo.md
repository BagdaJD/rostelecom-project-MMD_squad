# Сценарий демонстрации backend

Проект: «Экосистема коммерческого блока», кейс ПАО «Ростелеком».
Задача прототипа — связать поиск перспективных клиентов, наблюдение за инвестпроектами
и подготовку коммерческого предложения в одном процессе.

## Подготовка

Развернуть API, worker, PostgreSQL/PostGIS и Redis по
[инструкции](server-deployment.md). Применить миграции, загрузить кейс и калькулятор,
создать пользователя `manager`. Проверить `/api/v1/ready`: все сервисы должны быть готовы.
Для просмотра API открыть `/docs`; рабочие запросы выполняются с Bearer access token.

Данные кейса содержат 759 компаний и 63 проекта. Дополнительно создаются 60 отсутствующих
инициаторов без выдуманных идентификаторов. В Excel нет финансовой истории и присутствия
услуг; эти пропуски сохраняются. Для демонстрации заполненных финансовых срезов есть
отдельный `DATA_MODE=demo` на отдельной БД; его данные явно синтетические.

## Основной путь

| Шаг | Что показать | Что проверяется |
|---|---|---|
| Вход | Пароль → настройка/проверка TOTP → access token | Пароль сам по себе не открывает рабочие API |
| Радар | Компании, карточка, метрики, карта потенциала, наблюдения | Фильтры, происхождение, объяснения и корректные пропуски |
| Навигатор | Проект, инициатор, стадия, сроки, потребности | Единые компании/проекты, годовая точность дат и доказательство правил |
| Калькулятор | Черновик из проекта → уточнить параметры → расчёт | Каталог, себестоимость, аналоги, ценовая вилка и ограничения |
| Утверждение | Менеджер подтверждает цену своего расчёта | Права, границы цены и аудит |
| Предложение | Скачать DOCX, CSV или CRM | Воспроизводимые данные расчёта и защищённый доступ |
| Фоновая выгрузка | `POST /exports` → статус → файл | Работа worker и выгрузка больших выборок |
| Подписка | Сохранить условия, затем импортировать новое событие | Уведомление по фильтрам и частоте без дублей |

## Проверки границ

- Чужой расчёт или файл возвращает 404; analyst не утверждает цену.
- Повторный импорт не создаёт новые компании/проекты; изменённая строка сохраняет источник.
- Неизвестная выручка остаётся `null`, известный ноль не пропадает.
- Год источника не показывается как подтверждённые 1 января или точный срок работ.
- Радар показывает белые пятна только при достаточных данных о потенциале и присутствии.
- Сигнал другого региона не заявляет доказанное открытие филиала.
- При отсутствии актуальной модели калькулятор сообщает о резервном расчёте.
- Большой экспорт доступен владельцу или администратору и сохраняет текущие фильтры.

## Подтверждение реализации

154 переносимых теста проверяют бизнес-правила и HTTP-сценарии. В частности, проверены
620 событий уведомлений, пересекающиеся подписки, rollback, экспорт 5003 строк,
восстановление задачи после сбоя, доступ к файлам, источники, модель и сохранённые фильтры.
21 отдельная интеграционная проверка требует реальных PostgreSQL/PostGIS и Redis.
Она обязательна для серверной приёмки; переносимые тесты её не заменяют.

Скоринг радара — экспертная эвристика, определение потребностей — правила.
Каталог калькулятора взят из кейса, обучающая история включает синтетические данные.
Точность на реальных продажах и время ответа на целевом сервере пока не подтверждены.
Внешние подключения ФНС/ЕИС требуют согласованного доступа.

## Просмотр интерфейса без серверного окружения

Во frontend уже есть режим `?mock=1`. Он показывает демонстрационные ответы без БД.
Логин `demo`, пароль `demo12345`, код `123456` подходят только этому режиму.
Это демонстрация экранов; расчёты, файлы и вход здесь не подтверждают работу backend.
Для проверки backend моки должны быть отключены и использованы реальные сервисы.

Контракты входа/сессий, годовых дат и фоновых экспортов описаны в
[документации доступа](auth-and-access.md), [данных](case-data-api.md) и
[фоновых задач](background-and-run.md). Клиентская команда подключает эти контракты
при общей проверке веб-приложения.
